# v1.4.6（2026-11-27）—— 归档流程末尾补「打包与邮件外发」环节

## 背景
既有工作流止于清理原件，材料归集校验通过后如何打包、走哪个邮箱通道、发送前后如何核对，没有成文规范。本轮办理鸿鑫物流 2026 年 1-3 月运输吊装结算：先试飞书邮箱 CLI，当前账号无可用发件邮箱（主地址为空、建草稿报 `From address is required`、可访问邮箱列表为空、`send_as` 权限拒绝），随后改用浏览器网页版邮箱完成材料外发，并在已发送箱核对到「投递成功」。据此把全过程总结优化为可复用环节。

## 本轮新增
- [x] `rules/mail-delivery.md`：结算材料打包与邮件外发完整流程。
  - **渠道判定**：先 CLI 后网页；列出 CLI 不可用的四类信号；禁止编造发件地址。
  - **打包口径**：按 01 请示报告 / 02 合同协议 / 03 结算单 / 04 工作量确认单 / 05 现场佐证归集；排除备查件、下期材料、旧口径件、待确认扫描件；包名 `{供应商简称}{结算期次}结算材料.zip`；金额以对账复核值为准。
  - **写信核对**：收件人必须核对完整邮箱（昵称标签只显示 `@` 前缀，防止误匹配联系人）；主题 `{供应商}{结算期次}结算材料`；正文首屏给含税合计、逐主体列金额、注明双章与专票待批复后办理；附件等卡片出现文件名 + 大小。
  - **发送与回执**：登录/扫码/验证码交用户接管；发送属不可逆动作，须用户明确同意；发送后进「已发送」箱核对，列表有缓存需刷新；核对收件人、附件名大小、状态「投递成功」；未入列先查草稿/退信，不重复盲发。
- [x] 根 `SKILL.md`：
