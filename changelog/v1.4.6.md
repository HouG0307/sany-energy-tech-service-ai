# v1.4.6 —— 归档流程末尾补「打包与邮件外发」环节

## 背景
既有工作流止于清理原件；材料归集校验通过后如何打包、走哪个邮箱通道、发送前后如何核对，缺少成文规范。本轮把外发全过程梳理为可复用的通用环节，写入仓库供后续所有结算批次调用。本记录只描述规则变更，不包含任何具体批次的主体、金额、收件邮箱或邮件会话。

## 本轮新增
- [x] `rules/mail-delivery.md`：结算材料打包与邮件外发完整流程。
  - **触发与批次定位**：收到外发指令后先确认供应商、期次、项目/主体、归档路径；本机个人使用默认绑定收件邮箱 `hujj21@sany.com.cn`，指令另指邮箱以指令为准（指令即授权）；他人从 git 部署由下载者本人在自己电脑上确认绑定、自主决定收件地址，无需联系原负责人，未确认不得沿用默认地址；地址存疑先核对，查不到不进入写信。
  - **渠道判定**：先 CLI 后网页；列出 CLI 不可用的四类信号；禁止编造发件地址。
  - **打包口径**：按 01 请示报告 / 02 合同协议 / 03 结算单 / 04 工作量确认单 / 05 现场佐证归集；排除备查件、下期材料、旧口径件、待确认扫描件；包名 `{供应商简称}{结算期次}结算材料.zip`；金额以对账复核值为准，税率不混算。
  - **写信核对**：收件人核对完整邮箱（昵称标签只显示 `@` 前缀，防止误匹配联系人）；主题 `{供应商}{结算期次}结算材料`；正文首屏给含税合计、逐主体列金额、注明双章与专票待批复后办理；附件等卡片出现文件名 + 大小。
  - **发送与回执**：登录 / 扫码 / 验证码交当前操作者本人接管；发送属不可逆动作，须当前操作者本人明确同意（他人部署即下载者本人，无需原负责人参与）；发送后进「已发送」箱核对，列表有缓存需刷新；核对收件人、附件名大小、状态「投递成功」；未入列先查草稿 / 退信，不重复盲发。
  - **交付留痕**：投递成功后在本地 `output/`（gitignore）记一条外发记录，凭据与会话不入库。
- [x] 根 `SKILL.md`：
  - 触发条件补外发 / 邮件指令；工作流补第 8 步「打包与外发」；
  - 新增「打包与邮件外发（强制）」小节指向 `rules/mail-delivery.md`；
  - 禁止事项补：不代输邮箱密码 / 验证码、不编造收发件人地址、发送前须确认。

## 入库边界
- 仓库只存流程、规则、空白模板；真实合同 / 发票 / 结算数据、邮件会话、收件信息、外发记录均留在本机，不提交 git。
